# B. 사전조건서 — AWS에 무엇이 필요한가

> 실험을 시작하기 전에 준비해야 하는 **AWS 리소스·계정·네트워크·소프트웨어 사전 조건**을 정리한 문서.
> 온프레미스 환경 기준으로 작성. **EKS 사전조건은 마지막 절에 자리만 두고 비워둠(예정).**

---

## 1. AWS 계정 · 리전 · 권한

| 항목 | 값 / 조건 |
|---|---|
| 리전 | **ap-northeast-2 (서울)** |
| 인스턴스 유형 | **중첩 가상화 지원** 인스턴스 (c8i 계열) — KVM을 EC2 안에서 돌려야 함 |
| 구매 옵션 | **스팟 인스턴스** (인프라 검증 후 종료 예정 → 온디맨드 불필요) |
| 키 페어 | SSH 접속용 키페어 1개 (예: `aws-3tier-keypair.pem`) |
| IAM | EC2 생성·AMI 생성·스냅샷·(EKS 단계에서) eksctl 권한 |

> ⚠️ **중첩 가상화는 스팟 요청 페이지에서 직접 켤 수 없다.** Launch Template를 만들어 중첩 가상화를 활성화한 뒤 그 템플릿으로 인스턴스를 띄워야 KVM이 동작한다. (트러블슈팅 → `트러블슈팅.md`)

## 2. EC2 인스턴스 구성 (온프레미스 + 공통 인프라)

| EC2 | 스펙 | OS | 역할 |
|---|---|---|---|
| **K8s 호스트** | c8i.2xlarge (8 vCPU / 16 GB, 스팟) | Ubuntu 24.04 | KVM 가상머신 4대(master + worker1·2·3) + 호스트 iptables 포워딩 |
| **PostgreSQL** | (소형 EC2) | Ubuntu | Docker PostgreSQL 16 (`max_connections 300`) |
| **Redis** | (소형 EC2) | Ubuntu | Docker Redis 7 |
| **Monitoring** | (소형 EC2) | Ubuntu | Prometheus + Grafana |
| **k6** | (소형 EC2) | Ubuntu | 부하 생성기 |

> OS는 Ubuntu **24.04**(22.04는 스팟 가용성 문제로 회피). KVM VM은 Ubuntu **cloud image**(`.img`)를 받아 cloud-init으로 생성.

### KVM 가상머신 (호스트 EC2 내부)

| VM | 스펙 | 역할 |
|---|---|---|
| master | 2 vCPU / 4 GB | k8s 컨트롤플레인 (kubeadm) |
| worker1 (실험) | 2 vCPU / 4 GB | gateway, product, inventory |
| worker2 (실험) | 2 vCPU / 4 GB | frontend, order, payment, user |
| worker3 (운영) | 2 vCPU / 4 GB | Nginx Ingress · MetalLB · kube-state-metrics 등 (taint 격리) |

## 3. 네트워크 · Security Group

VM은 공인 IP가 없으므로 호스트 EC2가 **iptables DNAT**로 트래픽을 전달한다.

| SG | 핵심 인바운드 | 소스 |
|---|---|---|
| **K8s EC2** | 22(SSH) / 80·443(부하 진입) / 30400~30404·30800·391xx·380xx(메트릭) | 내 IP / k6 SG / 모니터링 SG |
| **PostgreSQL EC2** | 22 / 5432(DB) / 9187(exporter) / 9100 | 내 IP / K8s SG / 모니터링 SG |
| **Redis EC2** | 22 / 6379(Redis) / 9121(exporter) / 9100 | 내 IP / K8s SG / 모니터링 SG |
| **Monitoring EC2** | 22 / 9090(Prometheus) / 3000(Grafana) | 내 IP / k6 SG |
| **k6 EC2** | 22 | 내 IP |

> 포트 전체 일람 → `포트정리.md`

## 4. 외부 서비스 · 레지스트리

| 항목 | 용도 |
|---|---|
| **GitHub 저장소** | 앱 소스 + 매니페스트 |
| **GitHub Actions** | `git push → 이미지 빌드 → GHCR 푸시` |
| **GHCR** (`ghcr.io/ktk026/shoply-*`) | 7개 서비스 컨테이너 이미지 |
| **GHCR imagePullSecret** | 클러스터가 비공개 이미지 pull 시 인증 |
| 도메인 (`shoply.example.com`) | `/etc/hosts` → EIP 매핑(테스트용) |

> ⚠️ 자격증명(GHCR 토큰, DB 비밀번호, JWT 시크릿)은 **절대 코드/문서에 평문으로 남기지 않는다.** Kubernetes Secret으로 관리.

## 5. 호스트 / VM 소프트웨어 사전 설치

| 위치 | 설치 |
|---|---|
| 호스트 EC2 | KVM/libvirt, virt-install, cloud-image-utils, iptables-persistent |
| 각 VM | containerd, kubeadm/kubelet/kubectl(v1.34.x), Flannel CNI(v0.26.7) |
| master VM | metrics-server, Nginx Ingress(helm), MetalLB, helm |
| 호스트 OS 공통 | `net.ipv4.ip_forward=1`, swap off, 커널 모듈(br_netfilter 등) |

> ⚠️ `net.ipv4.ip_forward`를 OS 공통설정에 빠뜨리면 `kubeadm init` 전에 수동 적용해야 한다(트러블슈팅 사례). 설치 누락 반복을 막으려면 절차를 문서로 고정해 재현한다.

## 7. 백업 · 복구 사전 준비 (스팟 대비)

스팟 인스턴스는 회수되면 root EBS가 함께 삭제되므로 백업 체계가 필수.

| 방식 | 내용 |
|---|---|
| **AMI 백업** | 호스트 EC2를 AMI로 떠두면 KVM VM 디스크(qcow2)까지 포함 → 몇 분 내 복구 (`AMI백업_복원.md`) |
| 복원 후 갱신 | 호스트 사설 IP는 매번 바뀌므로 iptables DNAT·ConfigMap의 DB/Redis IP 갱신 필요 |

## 9. EKS 사전조건 (예정)

> EKS 환경 구축 시 채울 항목 — 현재는 자리만 둔다.

| 항목 | 값 (목표) |
|---|---|
| 클러스터 | EKS v1.34.x (eksctl) — 온프레와 동일 마이너 |
| 워커 노드 | EC2 t3.medium(2 vCPU/4 GB) × 2 — 온프레 VM과 동일 스펙 |
| 노드 확장 | **Karpenter** (NodePool: t3.medium, cpu limit로 비용 보호) |
| DB | RDS PostgreSQL 16 (`max_connections 300`), 선택 시 Multi-AZ |
| 진입 | NLB (ingress-nginx `type: LoadBalancer`) — 온프레 MetalLB와 대칭 |
| 인증 | IRSA 또는 동일 imagePullSecret |

> 상세 동일화 기준 → `동일화.md`
