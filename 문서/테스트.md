## 공통 — 빌드 & 컨테이너 관리

```bash
cd msa_shoply

# 전체 재빌드 (처음 시작 또는 코드 변경 시)
docker compose down && docker compose up -d --build

# 특정 서비스만 재빌드
docker compose up -d --build user
docker compose up -d --build product
docker compose up -d --build inventory

# 컨테이너 상태 확인
docker compose ps

# 특정 서비스 로그 실시간 확인
docker compose logs -f gateway
docker compose logs -f user
docker compose logs -f product
docker compose logs -f inventory
```

**정상 상태 (1~3차 기준):**

```
NAME             STATUS
msa_postgres     Up (healthy)
msa_redis        Up (healthy)
msa_user         Up
msa_gateway      Up
msa_frontend     Up
msa_product      Up
msa_inventory    Up
```

> DB가 먼저 `healthy` 상태가 돼야 서비스들이 뜬다.  
> `msa_postgres` 가 unhealthy면 `docker compose logs postgres` 로 원인 확인.

### 재고 조회

```bash
ID=$(curl -s http://localhost:4000/api/products | jq -r '.[0].id')

curl -s http://localhost:4000/api/inventory/$ID | jq
```

**기대 응답:**

```json
[
  { "size": 240, "quantity": 90, "reserved": 0, "available": 90 },
  { "size": 250, "quantity": 46, "reserved": 0, "available": 46 },
  { "size": 260, "quantity": 16, "reserved": 0, "available": 16 },
  { "size": 270, "quantity": 47, "reserved": 0, "available": 47 },
  { "size": 280, "quantity": 37, "reserved": 0, "available": 37 },
  { "size": 290, "quantity": 21, "reserved": 0, "available": 21 }
]
```

> `available = quantity - reserved`

---

### 재고 예약 (reserve)

주문 생성 시 Inventory Service를 호출해 재고를 선점한다.

```bash
ID=$(curl -s http://localhost:4000/api/products | jq -r '.[0].id')

curl -s -X POST http://localhost:4000/api/inventory/reserve \
  -H "Content-Type: application/json" \
  -d "{\"productId\":\"$ID\",\"size\":270,\"quantity\":2}" | jq
# 기대: { "ok": true, "available": 45 }
```

**예약 후 재고 변화 확인 (reserved 증가):**

```bash
curl -s http://localhost:4000/api/inventory/$ID \
  | jq '.[] | select(.size == 270)'
# 기대: reserved: 2, available: 45 (= 47 - 2)
```

**재고 초과 예약 → 409:**

```bash
curl -s -X POST http://localhost:4000/api/inventory/reserve \
  -H "Content-Type: application/json" \
  -d "{\"productId\":\"$ID\",\"size\":270,\"quantity\":99999}" | jq
# 기대: 409
# { "message": "재고가 부족합니다.", "available": 45, "requested": 99999 }
```

---

### 동시 예약 — SELECT FOR UPDATE 검증

10개의 요청을 동시에 보내 재고 정합성을 검증한다.

```bash
ID=$(curl -s http://localhost:4000/api/products | jq -r '.[0].id')

for i in {1..10}; do
  curl -s -X POST http://localhost:4000/api/inventory/reserve \
    -H "Content-Type: application/json" \
    -d "{\"productId\":\"$ID\",\"size\":260,\"quantity\":3}" &
done
wait
```

**검증 기준:**

```
초기 재고(260사이즈): 16
→ 3개씩 예약 → 최대 5건(15개)까지만 성공, 나머지 409

성공 건수 × 3 ≤ 16  (정합성 보장)
성공 건수 + 실패 건수 = 10
```

**DB에서 직접 확인:**

```sql
-- psql에서
SELECT quantity, reserved, quantity - reserved AS available
FROM inventory
WHERE product_id = '<ID>' AND size = 260;
```

---

### 예약 해제 (release)

결제 실패 시 예약한 재고를 돌려준다.

```bash
curl -s -X POST http://localhost:4000/api/inventory/release \
  -H "Content-Type: application/json" \
  -d "{\"productId\":\"$ID\",\"size\":270,\"quantity\":2}" | jq
# 기대: { "ok": true }
```

**해제 후 reserved 원복 확인:**

```bash
curl -s http://localhost:4000/api/inventory/$ID \
  | jq '.[] | select(.size == 270)'
# 기대: reserved 다시 0으로 돌아옴
```

---

### 재고 실차감 (deduct)

결제 성공 시 quantity를 영구 차감한다.

```bash
curl -s -X POST http://localhost:4000/api/inventory/deduct \
  -H "Content-Type: application/json" \
  -d "{\"productId\":\"$ID\",\"size\":250,\"quantity\":1}" | jq
# 기대: { "ok": true }
```

**차감 후 quantity 변화 확인:**

```bash
curl -s http://localhost:4000/api/inventory/$ID \
  | jq '.[] | select(.size == 250)'
# 기대: quantity: 45 (= 46 - 1), reserved: 0, available: 45
```

**Inventory 흐름 요약:**

```
주문 생성 → reserve   (reserved ↑, quantity 유지)
결제 성공 → deduct    (quantity ↓, reserved ↓)
결제 실패 → release   (reserved ↓, quantity 유지)
```

## 전체 흐름 통합 테스트

로그인 → 상품 조회 → 재고 확인 → 주문 생성 → 결제 → 결과 검증 한 번에 실행.

```bash
# ── 1. 로그인 ─────────────────────────────────────────────────
TOKEN=$(curl -s -X POST http://localhost:4000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test1@shoply.com","password":"Test1234!"}' | jq -r '.token')
echo "TOKEN: $TOKEN"

# ── 2. 상품 조회 ──────────────────────────────────────────────
ID=$(curl -s http://localhost:4000/api/products | jq -r '.[0].id')
echo "PRODUCT_ID: $ID"

# ── 3. 주문 전 재고 확인 ─────────────────────────────────────
BEFORE=$(curl -s http://localhost:4000/api/inventory/$ID \
  | jq '.[] | select(.size == 270) | .available')
echo "결제 전 270 재고: $BEFORE"

# ── 4. 주문 생성 (재고 자동 예약) ─────────────────────────────
ORDER=$(curl -s -X POST http://localhost:4000/api/orders \
  -H "Content-Type: application/json" \
  -d "{\"items\":[{\"productId\":\"$ID\",\"size\":270,\"quantity\":1}]}" | jq -r '.orderId')
echo "ORDER_ID: $ORDER"

# ── 5. 예약 후 reserved 확인 ─────────────────────────────────
curl -s http://localhost:4000/api/inventory/$ID \
  | jq '.[] | select(.size == 270)'
# 기대: reserved 1 증가

# ── 6. 결제 처리 ──────────────────────────────────────────────
PAY=$(curl -s -X POST http://localhost:4000/api/payments \
  -H "Content-Type: application/json" \
  -d "{\"orderId\":\"$ORDER\",\"method\":\"card\"}")
echo "결제 결과: $(echo $PAY | jq -r '.status')"
echo $PAY | jq

# ── 7. 결제 후 재고 확인 ──────────────────────────────────────
AFTER=$(curl -s http://localhost:4000/api/inventory/$ID \
  | jq '.[] | select(.size == 270) | .available')
echo "결제 후 270 재고: $AFTER"
# PAID면 → $BEFORE - 1, FAILED면 → $BEFORE 유지

# ── 8. 실시간 통계 ────────────────────────────────────────────
curl -s http://localhost:4000/api/stats | jq '{total,success,failed,rate}'
```

**전체 흐름 성공 기준:**

```
로그인        → token 발급
상품 조회     → 상품 목록 반환
재고 확인     → available > 0
주문 생성     → orderId 반환, reserved 증가
결제 처리     → status: PAID, quantity 차감, reserved 0
통계          → paid 건수 증가
```
