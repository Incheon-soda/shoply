온프레미스 k8s vs AWS EKS

인프라 운영 비교 실험 — 전체 계획
앱·부하·설정을 전부 똑같이 맞추고,
"노드가 자동으로 늘어나냐" 딱 하나만 다르게 둬서
폭증·장애 때 어떻게 갈리는지 본다.

1. 무엇이 같고 무엇이 다른가

구분내용
같음 (공정성)앱 이미지 · k6 부하 · 데이터 · Nginx Ingress · 리소스 100m/500m · HPA 60%
다름 ★실험 대상온프레: 노드 고정 + DB 수동복구 ↔ EKS: Karpenter 자동 + RDS 자동복구

2. 시나리오 3개

상황온프레EKS
A부하 점점 증가Pending 쌓임 → Error↑노드 추가 → 버팀
B워커노드 죽임복구 수 분복구 60초
CDB 죽임수동 승격 수 분RDS 자동 60초

A=한계 측정 · B=노드 장애 MTTR · C=DB 페일오버 MTTR

3. 핵심 측정 지표

  • ★ Pending Pod — 온프레 한계의 증거
  • ★ Node Count — EKS 자동 확장
  • MTTR — 장애 복구 시간 (B·C)
  • Error율 · 결제 성공/실패 · DB 커넥션

4. 부하 방식 (핵심)

코드를 무겁게 하지 않고, request 100m(작게) + k6 RPS 크게로 HPA를 발동시킨다.
→ 실제CPU ÷ request가 60% 쉽게 넘어 파드가 늘고, 노드가 차면 온프레 Pending vs EKS 노드추가로 갈린다.

5. 진행 순서

1리허설 (A를 500 RPS로 → 설정 확정)
2DB 리셋 + 양쪽 동시 시작
3A → B → C 순서로 측정
4한계 RPS / MTTR 비교 정리
