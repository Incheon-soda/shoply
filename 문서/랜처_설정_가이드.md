# Rancher 설정 가이드 — 온프레미스 + EKS 통합 관리

> **목적:** 온프레미스와 EKS 두 클러스터를 Rancher 한 화면에서 보고, 배포 난이도를 비교한다.
>
> **역할:** 관리 UI / 통합 뷰 데모 / 배포 비교 — **실험 측정용이 아님.**
>
> ⚠️ **원칙:** 실험 측정(시나리오 A/B/C)은 순수 k8s + Grafana로 한다.
> Rancher는 "관리·배포·시각화"용으로만 쓴다. (이유는 §8 참고)

---

## 0-1. Rancher가 뭔가 / 왜 쓰나 / 좋은 점

### 뭔가

**여러 k8s 클러스터를 웹 UI로 관리하는 플랫폼** (SUSE 제품).
kubectl 명령 대신 화면에서 클릭으로 클러스터·노드·파드·배포를 관리한다.

### 왜 쓰나 (우리 프로젝트 기준)

```
지금: 온프레는 온프레 kubectl, EKS는 EKS kubectl — 따로따로
      두 클러스터 비교하려면 창 두 개, 명령 두 번

Rancher: 한 화면에서 온프레 + EKS 동시에
        → "노드 늘어나는 순간"을 나란히 시각적으로 비교
```

### 좋은 점

| 좋은 점 | 설명 |
|---|---|
| **멀티클러스터 통합 뷰** | 온프레 + EKS를 한 화면에 → 발표 시각 임팩트 |
| **노드 증가 시각화** | EKS에 노드 박스가 실시간으로 생김 (Karpenter 작동을 눈으로) |
| **배포 생산성** | kubectl + YAML → 클릭 몇 번 (배포 난이도 비교 소재) |
| **kubectl 없이 관리** | 파드 재시작·로그·롤백을 GUI 버튼으로 |
| **학습 가치** | 실무 온프레가 쓰는 도구를 직접 경험 |

### 한계 (오해 방지)

> Rancher는 **"관리 편의"** 를 높일 뿐, **"노드 탄력성"** 은 못 바꾼다.
> Rancher를 깔아도 온프레는 노드를 자동으로 못 늘린다 (물리 서버 풀이 전제).
> → 실험 결론(고정 자원 vs 탄력 자원)은 그대로다.

---

## 0. 전체 그림

```
Rancher 서버 (별도 EC2 t3.medium)
  │ 웹 UI :443
  ├── import ──→ 온프레미스 k8s  (cattle-cluster-agent 설치됨)
  └── import ──→ EKS            (cattle-cluster-agent 설치됨)

→ 한 화면에서 두 클러스터의 노드·파드·배포를 나란히 관리
```

---

## 1. 사전 준비

### EC2 스펙

| 항목 | 값 |
|---|---|
| 인스턴스 | t3.medium (2 vCPU / 4GB) — Rancht single-node 최소 권장 |
| OS | Ubuntu 24.04 |
| 디스크 | 30GB 이상 |
| 위치 | VPC-A (모니터링 서버와 같은 곳) |
| EIP | 권장 (웹 UI 주소 고정) |

### Security Group (Rancher SG)

| 방향 | 포트 | 소스 | 이유 |
|---|---|---|---|
| 인바운드 | 443 | Admin IP/32 | Rancher 웹 UI (HTTPS) |
| 인바운드 | 80 | Admin IP/32 | HTTP → HTTPS 리다이렉트 |
| 인바운드 | 22 | Admin IP/32 | SSH |
| 아웃바운드 | 6443 | 온프레/EKS API Server | 클러스터 관리 통신 |
| 아웃바운드 | 전체 | 0.0.0.0/0 | 이미지 pull 등 |

> import된 클러스터의 cattle-cluster-agent가 **Rancher로 먼저 연결**하는 구조(아웃바운드)라,
> 클러스터 쪽 SG에서 Rancher EIP로의 443 아웃바운드만 열려있으면 된다.

## 2. Rancher 설치 (Docker single-node)

가장 간단한 방식. EC2에 Docker만 있으면 한 줄로 뜬다.

```bash
# 1. Docker 설치
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker

# 2. Rancher 컨테이너 실행 (최신 안정 버전)
docker run -d --name rancher --restart=unless-stopped \
  -p 80:80 -p 443:443 \
  --privileged \
  rancher/rancher:latest
```

> **k8s 1.34 호환:** Rancher 2.10+ 사용 권장. `rancher/rancher:latest`가 보통 최신 안정.
> 특정 버전 고정하려면 `rancher/rancher:v2.10.x` 형태로 지정.

### 설치 확인

```bash
docker logs rancher 2>&1 | grep "Bootstrap Password"
# → 초기 비밀번호가 출력됨 (복사해둘 것)

docker ps | grep rancher   # Up 상태 확인
```

## 3. 초기 접속 설정

브라우저에서 `https://<Rancher-EIP>` 접속 (자체 서명 인증서라 경고 → 무시하고 진행)

```
1. Bootstrap Password 입력 (위 docker logs에서 복사한 값)
2. 새 admin 비밀번호 설정
3. Server URL 확인 → https://<Rancher-EIP> 로 설정
   (import한 클러스터가 이 주소로 연결하므로 정확해야 함)
```

## 4. 온프레미스 클러스터 Import

### 4-1. Rancher UI에서

```
좌측 메뉴 → Cluster Management
→ Import Existing
→ Generic 선택
→ 클러스터 이름: onprem
→ Create
```

### 4-2. 생성된 명령어를 온프레 마스터에서 실행

Rancher가 `kubectl apply` 명령을 보여줌. 복사해서 온프레 k8s 마스터에서 실행:

```bash
# 온프레 마스터 (lxc exec k8s-master 또는 직접)
kubectl apply -f https://<Rancher-EIP>/v3/import/xxxxx.yaml

# 자체 서명 인증서라 안 되면 --insecure 버전 명령 사용 (Rancher UI가 같이 제공)
curl --insecure -sfL https://<Rancher-EIP>/v3/import/xxxxx.yaml | kubectl apply -f -
```

→ 온프레 클러스터에 `cattle-system` 네임스페이스 + `cattle-cluster-agent` 파드가 설치됨.

### 4-3. 확인

```bash
kubectl get pods -n cattle-system
# cattle-cluster-agent 가 Running 되면 OK
```

Rancher UI에서 onprem 클러스터가 **Active** 로 바뀌면 성공.

## 5. EKS 클러스터 Import

EKS도 동일하게 **Generic import**가 가장 간단하다.

```
Cluster Management → Import Existing → Generic
→ 이름: eks → Create
→ 생성된 명령을 EKS에서 실행
```

```bash
# EKS 접속 후 (aws eks update-kubeconfig 된 상태)
curl --insecure -sfL https://<Rancher-EIP>/v3/import/yyyyy.yaml | kubectl apply -f -
```

> **대안:** Rancher의 "Amazon EKS" provider로 AWS credential을 넣어 import할 수도 있지만,
> Generic import가 더 단순하고 측정 영향이 적어 권장.

## 6. 통합 뷰 활용

두 클러스터가 Active 되면:

```
Cluster Management 화면
┌──────────────┬──────────────┐
│   onprem     │     eks      │
│  노드 2개    │   노드 2개   │
│  파드 N개    │   파드 N개   │
└──────────────┴──────────────┘
```

### 발표 데모 포인트

| 보여줄 것 | Rancher에서 |
|---|---|
| 노드 수 비교 | 두 클러스터 노드 개수 나란히 |
| **노드 증가 순간** | EKS에 노드 박스가 실시간으로 생김 (Karpenter 작동) |
| 파드 분포 | 어느 노드에 어떤 파드가 있는지 시각화 |
| Pending 파드 | onprem에 Pending 쌓이는 게 목록으로 보임 |

> Grafana는 "숫자 그래프", Rancher는 "클러스터 구조" — 둘이 상호보완.

## 7. 배포 난이도 비교 (발표 소재)

같은 서비스를 두 방식으로 배포해서 단계 수를 비교한다.

### 방식 A — 순수 k8s (kubectl)

```bash
# 1. 이미지 빌드 & push
docker build -t ghcr.io/.../shoply-order:v1 .
docker push ghcr.io/.../shoply-order:v1

# 2. YAML 작성 (deployment.yaml)
# 3. 적용
kubectl apply -f deployment.yaml

# 4. 외부 노출 위해 Ingress 별도 작성·적용
kubectl apply -f ingress.yaml
```
→ **단계 많음, YAML 직접 작성, CLI**

### 방식 B — Rancher UI

```
Workloads → Create
→ 이미지 입력: ghcr.io/.../shoply-order:v1
→ 포트/환경변수 폼에 입력
→ Create 클릭
→ (Ingress도 UI에서 폼으로)
```
→ **클릭 몇 번, YAML 안 봐도 됨, GUI**

### 비교표 (발표용)

| 단계 | kubectl | Rancher UI |
|---|---|---|
| 이미지 지정 | YAML에 직접 | 폼 입력 |
| 배포 | `kubectl apply` | 클릭 |
| 외부 노출 | Ingress YAML 별도 | 폼에서 체크 |
| 롤백 | `kubectl rollout undo` | 버튼 클릭 |
| 학습 곡선 | 높음 (YAML/CLI) | 낮음 (GUI) |

> **발표 메시지:** "관리 도구(Rancher/OCP)는 배포 생산성을 높이지만,
> 이건 '관리 편의' 레이어이지 '노드 탄력성'을 바꾸진 않는다."

## 8. ⚠️ 실험 오염 방지 (중요)

Rancher import 시 각 클러스터에 `cattle-cluster-agent`가 설치된다 — **워커노드 리소스를 약간 먹는다.**

### 측정에 영향을 막는 방법

| 방법 | 설명 |
|---|---|
| **측정은 Grafana로** | 시나리오 A/B/C 데이터는 Prometheus/Grafana에서 수집 (Rancher 무관) |
| **양쪽 동일 설치** | onprem·eks 둘 다 agent 설치 → 차이가 상쇄되어 공정성 유지 |
| **(선택) 측정 중 분리** | 엄격하게 하려면 본 측정 직전 agent 제거 → 측정 후 재import |

```bash
# 엄격 측정 시 agent 임시 제거
kubectl delete namespace cattle-system
# 측정 후 다시 import (§4-2 명령 재실행)
```

> 실용적으로는 **양쪽 동일 설치 + Grafana 측정**이면 충분. agent 부하는 수십 MB 수준으로 미미.

---

## 9. 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| 클러스터가 Active 안 됨 | agent가 Rancher에 연결 못 함 | Rancher Server URL 확인 + 클러스터→Rancher 443 아웃바운드 열기 |
| 인증서 오류로 import 실패 | 자체 서명 인증서 | `curl --insecure` 버전 명령 사용 |
| agent CrashLoop | Rancher 버전 ↔ k8s 버전 비호환 | Rancher 2.10+ 사용, 호환 매트릭스 확인 |
| 웹 UI 접속 안 됨 | SG 443 미개방 | Rancher SG 인바운드 443 확인 |
| Bootstrap Password 못 찾음 | 로그 흘러감 | `docker logs rancher 2>&1 \| grep Bootstrap` 재실행 |

## 10. 설치 순서 요약

```
1. t3.medium EC2 + EIP + SG(443/80/22)
2. Docker 설치 → rancher 컨테이너 실행
3. docker logs로 Bootstrap Password 확인
4. https://<EIP> 접속 → admin 비번 설정 → Server URL 확인
5. onprem 클러스터 Generic import (마스터에서 kubectl apply)
6. EKS 클러스터 Generic import
7. 둘 다 Active 확인 → 통합 뷰 완성
8. 배포 비교 데모 준비 (kubectl vs UI)
```

> **타이밍:** 온프레·EKS 클러스터가 떠 있어야 import 가능.
> 온프레만 먼저 import해서 연습 → EKS 뜨면 추가 import.
