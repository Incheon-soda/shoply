## 1. 프로젝트 개요

### 목적

동일한 쇼핑몰 MSA 애플리케이션을 온프레미스 k8s와 AWS EKS에 각각 배포하고,  
4가지 부하 시나리오에서 두 환경의 **확장성 · 복구력 · 운영 부담**을 비교 측정한다.

### 비교 핵심 지표

| 지표 | 측정 방법 |
|------|----------|
| Error Rate | prom-client → Prometheus → Grafana |
| Pending Pod 수 | kube-state-metrics |
| Node Count 변화 | kube-state-metrics (Karpenter 발동 확인) |
| MTTR (장애 복구 시간) | Grafana 타임라인 + OpenSearch 로그 타임스탬프 |
| 결제 손실 건수 | payment_processed_total (PAID/FAILED) |

### 4가지 실험 시나리오

| # | 이름 | 내용 | 확인 포인트 |
|---|------|------|-------------|
| 1 | 일반 트래픽 | 200 RPS, 20분 | 기준선 — 양쪽 정상 동작 확인 |
| 2 | 순간 폭증 | 타임세일 시작 + Locust 급증 | Pending Pod, Error Rate, Karpenter 발동 |
| 3 | 계단식 증가 | 200→400→600→800→1000 RPS | 온프레미스 한계 RPS 특정 |
| 4 | 장애 복구 | 워커노드 2 강제 종료 | MTTR 측정, 결제 손실 건수 |

## 2. 전체 아키텍처

```
AWS ap-northeast-2
│
├── VPC-A (10.0.0.0/16) ─── 온프레미스 환경
│   ├── c8i.2xlarge [EIP]          ← 온프레미스 k8s 호스트
│   │   └── LXD
│   │       ├── VM1 Master  (2vCPU/4GB, k8s v1.32.x)
│   │       ├── VM2 Worker1 (2vCPU/4GB) ← traffic-node
│   │       └── VM3 Worker2 (2vCPU/4GB) ← order-node
│   │
│   ├── t3.medium                  ← PostgreSQL 16 (Docker)
│   ├── t3.micro                   ← Redis 7 (Docker)
│   ├── t3.small [EIP]             ← Monitoring (Prometheus + Grafana)
│   ├── t3.medium                  ← Locust-A (온프레미스 부하)
│   └── t3.medium [EIP]            ← Locust-B (EKS 부하)
│
└── VPC-B (10.1.0.0/16) ─── EKS 환경
    ├── EKS Worker Node t3.medium [EIP]  ← traffic-node
    │   └── API Gateway, Product, Inventory 파드
    ├── EKS Worker Node t3.medium [EIP]  ← order-node
    │   └── Frontend, Order, Payment, User 파드
    ├── EKS Worker Node t3.medium        ← Karpenter 확장용
    ├── RDS db.t3.medium                 ← PostgreSQL 관리형
    └── t3.micro                         ← Redis 7 (Docker)
```

### 트래픽 흐름

**온프레미스:**
```
Locust-A → c8i.2xlarge:80 → EC2 Nginx → VM2:30080
  → kube-proxy → Nginx Ingress → API Gateway → 각 서비스
```

**EKS:**
```
Locust-B → Worker Node:30080 → kube-proxy → Nginx Ingress
  → API Gateway → 각 서비스
```

### 파드 고정 배치

| 노드 | 배치 서비스 | 이유 |
|------|------------|------|
| Worker1 (traffic-node) | API Gateway, Product, Inventory | 트래픽 집중 — 병목 관찰 |
| Worker2 (order-node) | Frontend, Order, Payment, User | 쓰기 트랜잭션 집중 |

## 3. MSA 서비스 구성

### 서비스 목록

| 서비스 | 포트 | 역할 | DB 사용 | Redis |
|--------|------|------|---------|-------|
| API Gateway | 4000 | 프록시 라우팅, 메트릭 집계 | ✗ | ✗ |
| User Service | 4005 | 회원가입, 로그인 (JWT) | ✓ users | ✗ |
| Product Service | 4001 | 상품 목록/상세, 타임세일 제어 | ✓ products | ✓ (캐시) |
| Inventory Service | 4002 | 재고 예약/차감/해제 | ✓ inventory | ✗ |
| Order Service | 4003 | 주문 생성/조회 | ✓ orders, order_items | ✗ |
| Payment Service | 4004 | 결제 처리, 통계 | ✓ payments | ✓ (stats 캐시) |
| Frontend | 80 | React SPA (nginx) | ✗ | ✗ |

### API Gateway 라우팅

| 경로 | 목적지 |
|------|--------|
| `/api/auth/*` | User Service :4005 |
| `/api/products/*` | Product Service :4001 |
| `/api/inventory/*` | Inventory Service :4002 |
| `/api/orders/*` | Order Service :4003 |
| `/api/payments/*` | Payment Service :4004 |
| `/api/stats` | Payment Service :4004/payments/stats |

### 핵심 로직

**재고 동시성 — SELECT FOR UPDATE:**
```sql
BEGIN;
SELECT quantity, reserved FROM inventory
WHERE product_id = $1 AND size = $2
FOR UPDATE;
UPDATE inventory SET reserved = reserved + $3
WHERE product_id = $1 AND size = $2;
COMMIT;
```

**결제 실패 시 DB 정합성 보장:**
```
결제 성공 → deduct 시도
  deduct 성공 → PAID
  deduct 실패 → release 후 FAILED (재고 예약 해제 보장)
결제 실패 (5%) → release 후 FAILED
```

**Redis 캐싱 대상:**

| 키 | TTL | 서비스 |
|----|-----|--------|
| `products:list` | 60s | Product |
| `products:{id}` | 30s | Product |
| `stats:realtime` | 3s | Payment |

## 4. 데이터베이스 스키마

### ERD 관계

```
users (1) ─── (N) orders (1) ─── (N) order_items
                    │
                   (1)
                    │
              payments (N)

products (1) ─── (N) inventory
     │
     └── (N) order_items (product_id 참조)
```

### 테이블 상세

#### users
```sql
CREATE TABLE users (
  id         UUID         PRIMARY KEY DEFAULT gen_random_uuid(),
  email      VARCHAR(255) UNIQUE NOT NULL,
  password   VARCHAR(255) NOT NULL,   -- bcrypt 해시
  name       VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```

#### products
```sql
CREATE TABLE products (
  id           UUID         PRIMARY KEY DEFAULT gen_random_uuid(),
  name         VARCHAR(255) NOT NULL,
  price        INTEGER      NOT NULL,          -- 정상가 (원)
  description  TEXT,
  image_url    VARCHAR(500),
  is_timesale  BOOLEAN      NOT NULL DEFAULT FALSE,
  sale_price   INTEGER,                        -- 세일가 (NULL = 세일 아님)
  sale_ends_at TIMESTAMPTZ,                    -- 세일 종료 시각
  created_at   TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```

#### inventory
```sql
CREATE TABLE inventory (
  id         UUID    PRIMARY KEY DEFAULT gen_random_uuid(),
  product_id UUID    NOT NULL REFERENCES products(id),
  size       INTEGER NOT NULL,                -- 신발 사이즈 (240~290)
  quantity   INTEGER NOT NULL DEFAULT 0,      -- 실제 재고
  reserved   INTEGER NOT NULL DEFAULT 0,      -- 결제 대기 중 예약 수량
  version    INTEGER NOT NULL DEFAULT 0,      -- 낙관적 락용
  UNIQUE (product_id, size)
);
-- available = GREATEST(0, quantity - reserved)
```

#### orders
```sql
CREATE TABLE orders (
  id            UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       UUID        REFERENCES users(id),
  status        VARCHAR(20) NOT NULL DEFAULT 'PENDING',
  -- PENDING | PAID | FAILED
  total_price   INTEGER     NOT NULL,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  paid_at       TIMESTAMPTZ,
  failed_at     TIMESTAMPTZ,
  failed_reason TEXT
);
```

#### order_items
```sql
CREATE TABLE order_items (
  id           UUID         PRIMARY KEY DEFAULT gen_random_uuid(),
  order_id     UUID         NOT NULL REFERENCES orders(id),
  product_id   UUID         NOT NULL,
  product_name VARCHAR(255) NOT NULL,
  size         INTEGER      NOT NULL,
  quantity     INTEGER      NOT NULL,
  unit_price   INTEGER      NOT NULL
);
```

#### payments
```sql
CREATE TABLE payments (
  id            UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  order_id      UUID        NOT NULL REFERENCES orders(id),
  method        VARCHAR(20) NOT NULL DEFAULT 'card', -- card | bank
  status        VARCHAR(20) NOT NULL,                -- PAID | FAILED
  amount        INTEGER     NOT NULL,
  failed_reason TEXT,
  -- PAYMENT_GATEWAY_ERROR | INSUFFICIENT_STOCK | INVENTORY_DEDUCT_FAILED
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 인덱스
```sql
CREATE INDEX idx_inventory_product_id  ON inventory(product_id);
CREATE INDEX idx_order_items_order_id  ON order_items(order_id);
CREATE INDEX idx_orders_status         ON orders(status);
CREATE INDEX idx_orders_user_id        ON orders(user_id);
CREATE INDEX idx_payments_order_id     ON payments(order_id);
CREATE INDEX idx_products_is_timesale  ON products(is_timesale);
```

## 5. 데이터베이스 구축 가이드

### 5-1. 온프레미스 — EC2 + Docker

PostgreSQL을 별도 EC2(t3.medium)에 Docker로 실행한다.

**EC2 사전 준비:**
```bash
# Docker 설치
sudo apt update && sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker ubuntu
```

**schema.sql, seed.sql 전송:**
```bash
# 로컬 Mac에서
scp -i ~/key/aws-3tier-keypair.pem \
  /Users/kimminseo/shopping_k8s/msa_shoply/db/schema.sql \
  /Users/kimminseo/shopping_k8s/msa_shoply/db/seed.sql \
  ubuntu@<PostgreSQL-EC2-공인IP>:~/
```

**PostgreSQL 컨테이너 실행:**
```bash
# PostgreSQL EC2에서
docker run -d \
  --name postgres \
  --restart always \
  -e POSTGRES_DB=shoply \
  -e POSTGRES_USER=shoply \
  -e POSTGRES_PASSWORD=shoply1234 \
  -v postgres_data:/var/lib/postgresql/data \
  -v ~/schema.sql:/docker-entrypoint-initdb.d/01_schema.sql \
  -v ~/seed.sql:/docker-entrypoint-initdb.d/02_seed.sql \
  -p 5432:5432 \
  postgres:16-alpine
```

> `docker-entrypoint-initdb.d/`에 마운트된 SQL은 컨테이너 최초 기동 시 자동 실행된다.  
> 이미 볼륨 데이터가 있으면 실행되지 않음 — 재초기화하려면 볼륨 삭제 후 재기동.

**접속 확인:**
```bash
docker exec -it postgres psql -U shoply -d shoply -c "\dt"
```

**보안그룹 설정:**

| 방향 | 포트 | 소스 |
|------|------|------|
| 인바운드 | 5432 | c8i.2xlarge SG (k8s 파드 → DB) |
| 인바운드 | 9187 | Monitoring SG (postgresql_exporter) |
| 인바운드 | 22 | Admin IP |

## 6. Redis 구축 가이드

Redis는 온프레미스 / EKS 양쪽 모두 **별도 EC2에 Docker로 실행**한다. (통제 변수 — 비교 대상 아님)

**Redis EC2에서:**
```bash
# Docker 설치
sudo apt update && sudo apt install -y docker.io
sudo systemctl enable --now docker

# Redis 컨테이너 실행
docker run -d \
  --name redis \
  --restart always \
  -p 6379:6379 \
  redis:7-alpine \
  --maxmemory 256mb \
  --maxmemory-policy allkeys-lru

# 접속 확인
docker exec -it redis redis-cli ping
# PONG
```

**실험 전 캐시 초기화:**
```bash
docker exec -it redis redis-cli FLUSHALL
# 또는 TTL 만료 대기 (products:list 60초)
```

**보안그룹 설정 (Redis SG):**

| 방향 | 포트 | 소스 |
|------|------|------|
| 인바운드 | 6379 | c8i.2xlarge SG (온프레미스) / Worker Node SG (EKS) |
| 인바운드 | 9121 | Monitoring SG (redis_exporter) |
| 인바운드 | 22 | Admin IP |

```
│   ├── inventory.yaml
│   ├── order.yaml
│   ├── payment.yaml
│   ├── gateway.yaml

│   └── hpa.yaml
├── onprem/              # 온프레미스 전용
```

### 배포 순서 — 온프레미스

```bash
# 0. k8s 파일을 마스터 컨테이너로 복사
lxc file push -r ~/k8s k8s-master/root/

# 1. 네임스페이스
lxc exec k8s-master -- kubectl apply -f /root/k8s/common/namespace.yaml

# 2. GHCR 이미지 pull 인증 Secret
lxc exec k8s-master -- kubectl create secret docker-registry ghcr-secret \
  --docker-server=ghcr.io \
  --docker-username=incheon-soda \
  --docker-password=<YOUR_GITHUB_TOKEN> \
  --namespace=shoply

# 3. ConfigMap (DB/Redis EC2 IP 설정됨) + Secret
lxc exec k8s-master -- kubectl apply -f /root/k8s/onprem/configmap-patch.yaml
lxc exec k8s-master -- kubectl apply -f /root/k8s/common/secret.yaml

# 4. 서비스 배포
lxc exec k8s-master -- kubectl apply -f /root/k8s/common/user.yaml
lxc exec k8s-master -- kubectl apply -f /root/k8s/common/product.yaml
lxc exec k8s-master -- kubectl apply -f /root/k8s/common/inventory.yaml
lxc exec k8s-master -- kubectl apply -f /root/k8s/common/order.yaml
lxc exec k8s-master -- kubectl apply -f /root/k8s/common/payment.yaml
lxc exec k8s-master -- kubectl apply -f /root/k8s/common/gateway.yaml
lxc exec k8s-master -- kubectl apply -f /root/k8s/common/frontend.yaml

# 5. HPA + Ingress
lxc exec k8s-master -- kubectl apply -f /root/k8s/common/hpa.yaml
lxc exec k8s-master -- kubectl apply -f /root/k8s/onprem/ingress.yaml

# 6. Prometheus scrape용 NodePort (옵션)
lxc exec k8s-master -- kubectl apply -f /root/k8s/onprem/nodeport-services.yaml

# 7. 상태 확인
lxc exec k8s-master -- kubectl get all -n shoply
```

```bash
  --type='json' \
  -p='[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--kubelet-insecure-tls"}]'
```

```bash

  --namespace ingress-nginx --create-namespace \
  --set controller.service.type=NodePort \
```
