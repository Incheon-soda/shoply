# EKS 포트 정리

> EKS 워커는 실제 EC2(공인IP 보유) → iptables 포워딩 불필요. NodePort 직접 접근.

## EKS Worker Node

| 포트 | 용도 | SG 인바운드 소스 |
|---|---|---|
| 80 | ingress-nginx (hostPort, 웹 트래픽) | k6 EIP |
| 30400~30404 | 앱 prom-client 메트릭 | 모니터링 EIP |
| 30800 | kube-state-metrics | 모니터링 EIP |
| 9100 | node_exporter (DaemonSet, hostPort) | 모니터링 EIP |
| 전체 | 노드 간 통신 (VPC CNI) | Worker Node SG |
| 10250 | kubelet API | Worker Node SG |
| 22 | SSH | 내 IP |

> ALB 미사용 — ingress-nginx를 hostPort 80으로 설정 → k6가 워커 공인IP:80 직접 타겟
> 온프레미스(EC2:80 → Nginx → VM:30080)와 동일하게 80으로 진입
> Prometheus 타겟: `<워커1-공인IP>:30400`, `<워커2-공인IP>:30400` ...

## 온프레 vs EKS 메트릭 접근 차이

| | 온프레미스 | EKS |
|---|---|---|
| 워커 노드 | KVM VM (NAT 뒤) | 실제 EC2 (공인IP) |
| 메트릭 접근 | EC2 → iptables DNAT → VM | 워커 공인IP 직접 |
| node_exporter 구분 | 39101/39102 (포트 변경) | 각 워커 공인IP:9100 |
| Prometheus 타겟 | K8s EC2 사설IP | 각 워커 공인IP |
